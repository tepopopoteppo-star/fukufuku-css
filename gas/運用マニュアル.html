3. 当日のスライド操作方法（再生）

各部の開始時刻になったら、その部のスライドファイルを開いて再生します。

再生の手順

  1. 該当する部のスライドファイルを開く
  2. 右上の 「スライドショー」 を押して全画面再生
  3. マウスを軽く動かす → 画面左下のツールバーが出る
  4. 「⋮」(その他) → 「自動再生」 で送り間隔（例:5〜10秒）、「ループ」にチェック

音楽について

  • 音楽は各ファイルの表紙（1枚目）に設定します（自動再生・ループ）。
  • 再生を始めれば自動で流れ、スライドを送っても止まりません。
  • 音が出ないとき:ブラウザ音量・PC音量・表紙のスピーカー設定（書式設定オプション→自動再生）を確認。
✅ より安定させたいとき ファイル → 共有 → ウェブに公開 で「○秒ごとに切替＋ループ」を設定し、出てきたリンクを開いて全画面にすると、操作不要で流しっぱなしにできます。

4. よくある運用作業

4-1. 📷 お客様の写真を差し替えたい

【推奨・恒久的】スプレッドシートを直す

  1. 新しい写真を Googleドライブにアップロード
  2. その写真を開き、URLの …/d/ と /view の間がファイルID
  3. 回答スプレッドシートで該当お客様の行を探す
  4. 「ペットちゃんのお写真…」列のセルを新URLに書き換える
    形式: https://drive.google.com/open?id=（新ファイルID）（複数はカンマ区切り・先頭1枚を使用）
  5. 写真ファイルの共有を、少なくとも運用アカウントが見られる状態に（同じアカウントのドライブ内なら問題なし）
  6. rebuildAllSlides を実行して作り直す
⚠️ 当日限りの応急処置 スライド上の写真を右クリック →「画像を置き換える」でも差し替え可。ただし次に rebuildAllSlides を実行すると元に戻ります。

4-2. 🔀 お客様の「部（参加時刻）」が変更になった

  1. 回答スプレッドシートで該当行を探す
  2. 「参加希望時刻」列のセルを新しい部に書き換える（「第2部」のように 第◯部 が入っていれば自動判定）
  3. rebuildAllSlides を実行 → そのペットは自動で正しい部のファイルへ移動します

4-3. ✏️ 名前・ふりがな・メッセージを直したい

  1. スプレッドシートの該当セルを書き換える
  2. rebuildAllSlides を実行

4-4. ❌ 申込がキャンセルになった

  1. スプレッドシートで該当行をまるごと削除（行番号を右クリック→削除）
  2. rebuildAllSlides を実行 → スライドが消えます

5. スライドを最新化する（rebuildAllSlides）

いつ実行する？ → スプレッドシートを編集したあと／本番直前に。

手順

  1. スプレッドシート → 拡張機能 → Apps Script
  2. 上部の関数プルダウンで rebuildAllSlides を選ぶ
  3. ▶ 実行
  4. 3つのスライドファイルを開いて並び・内容を確認
ℹ️ 何が起きるか 3ファイルそれぞれで表紙以外を消して、シートの最新内容で作り直します。各部のペットは第◯部の順に並び、末尾に締めスライドが付きます。
表紙（音楽含む）は残り、自動送り・ウェブ公開の設定もファイルごとに保持されます。

6. スタッフ共有サマリー（申込状況の共有）

申込状況をスタッフに見せたいが編集はさせたくないためのしくみです。元の回答シートは共有せず、専用の閲覧用ファイルを使います。

6-1. サマリーを作る・更新する

  1. Apps Script で updateStaffSummary を実行
  2. 初回は新しいファイル「スタッフ共有_ペット供養祭_申込状況」が自動作成され、実行ログにURLが出る
  3. 申込が増えたら再実行で最新化（onFormSubmit に組み込めば申込ごとに自動更新）

6-2. サマリーの場所

探し方方法
初回updateStaffSummary の実行ログに出る「★…URL」を開く
2回目以降ドライブで「スタッフ共有」と検索／「最近使用したアイテム」

6-3. スタッフへ共有（重要）

  1. サマリーファイルの右上 「共有」
  2. スタッフのメールアドレスを追加 → 権限を 「閲覧者」 に
⚠️ 個人情報の取り扱い 一覧には電話番号が含まれます（メール・住所は除外済み）。「リンクを知っている全員」ではなく、スタッフのアカウントを個別指定で共有してください。

7. Apps Script の関数一覧

関数名いつ使う何をする
rebuildAllSlides本番前・データ修正後3ファイルを最新データで作り直す（主役）
updateStaffSummary申込状況を共有・更新したいときスタッフ共有サマリーを作成・更新
diagnoseLatestResponse写真が出ない等のトラブル時最新申込の列・写真・ドライブ権限を診断
generateSampleSlides動作テストサンプル5件を各部ファイルに振り分けて生成
insertTitleSlide表紙を作り直すとき表紙（虹デザイン）を入れる
insertClosingSlide締めだけ入れ直すとき締めスライドを末尾に追加
onFormSubmit（自動・触らない）申込ごとに自動実行:確認メール＋スライド追加＋サマリー更新
⚠️ 注意 onFormSubmit はフォーム送信トリガーで自動的に動きます。手動実行しないでください（エラーになります）。

8. トラブル時の確認

写真が表示されない

  1. diagnoseLatestResponse を実行 → 実行ログを見る
  2. 確認:写真 idx= が正しい列か／✓ DriveApp OK が出るか／写真ファイルの共有設定

並び順がおかしい／古い内容のまま

→ rebuildAllSlides の実行忘れがないか確認（編集はシート→作り直しで反映）

名前やメッセージの列がずれた（フォーム項目を足した後など）

通常は自動で吸収します。ずれたら diagnoseLatestResponse で列対応を確認。見出しの言い回しが大きく変わった場合は COLUMN_KEYS の調整（開発者対応）。

確認メールが届かない／定員が効かない

SESSIONS の各部が、フォーム選択肢と「第◯部」レベルで一致しているか確認。

サマリーが見当たらない

ドライブで「スタッフ共有」と検索。まだ無ければ updateStaffSummary を実行すると作られます。

9. 設定変更（コード編集＝開発者向け）

スプレッドシート操作では完結せず、Apps Script のコード編集が必要な作業です。

やりたいこと変更箇所
部の追加・削除・時間変更SESSIONS と SLIDE_IDS（部を増やすならスライドファイルも新規作成しID追加）
定員・アラート人数SESSIONS の capacity / alert
背景画像BG_IMAGE_ID を新ファイルIDに → rebuildAllSlides
締めの言葉・表紙insertClosingSlide / insertTitleSlide 内のテキスト
サマリーの項目updateStaffSummary の列定義

10. ⚠️ やってはいけない / 注意

  • ❌ スライドを手で直して満足しない → rebuildAllSlides で消えます。直すならシート。
  • ❌ 音楽を2枚目以降に入れる → 作り直しで消えます。必ず表紙（1枚目）に。
  • ❌ onFormSubmit を手動実行しない（自動トリガー専用）。
  • ❌ スプレッドシートの1行目（見出し）を削除・改変しない（列の判定に使用）。
  • ❌ サマリーを「リンクを知っている全員」で公開しない（電話番号を含むため）。
  • ✅ 大きな作業前は、スライドファイルを「コピーを作成」でバックアップ。

11. 本番前チェックリスト

  • スプレッドシートの申込内容が最新・正確か
  • updateStaffSummary でサマリーを最新化し、スタッフ共有済みか
  • rebuildAllSlides を実行した
  • 第1部・第2部・第3部の各ファイルを開き、内容と並びを確認した
  • 各ファイルの表紙に音楽が入り、自動再生・ループになっている
  • 各ファイルの自動送り秒数を設定した
  • 締めスライドが各ファイルの最後に入っている
  • 会場PCで通し再生し、音・速度・写真表示を確認した
困ったときは、diagnoseLatestResponse の実行ログを控えて開発担当に共有してください。
